# 0007. 화합물마다 격리된 자식 프로세스로 도킹

## 맥락
리간드 준비(RDKit 형태 생성, 힘장 최적화, Meeko)와 Vina/QVina 엔진 호출은 네이티브 코드라 같은 프로세스 안에서는 시간 제한을 걸 수 없고, 멈추거나 비정상 종료하면 실험 전체가 함께 죽는다. 사이클 안의 여러 화합물을 동시에 도킹하면서도 결과가 처리 순서에 좌우되면 안 됐다.

## 결정
`DockingOracle.evaluate`는 화합물마다 새 디렉터리에 `request.json`을 쓰고, 호출 쪽이 import한 `docking.py` 절대 경로를 `--worker` 모드로 새 세션(프로세스 그룹)에서 실행한다. `docking.timeout`은 준비와 모든 형태의 엔진 실행 전체에 적용되며, 시간 초과·중단 시 POSIX에서는 프로세스 그룹 전체를 SIGKILL하고 정리 대기는 최대 1초다. 자식 프로세스에는 스레드 변수 1과 빈 `CUDA_VISIBLE_DEVICES`를 준다. 동시 실행은 파이프라인의 스레드 풀(`docking.workers`)이 각자 자식 프로세스를 띄우는 방식이다. 화합물·형태 시드는 실험 시드·ID·구조의 해시로 정한다.

## 대안
- **같은 프로세스에서 엔진 호출**: 네이티브 호출에 시간 제한을 걸 수 없고 장애가 실험 전체로 번져 채택하지 않음.

## 결과
- 화합물마다 프로세스 생성과 수용체 로드 비용이 든다. 매우 빠른 설정에서는 이 오버헤드가 도킹 시간보다 클 수 있다.
- 워커 수를 바꿔도 관측·질의 순서·예산 계산·포즈 바이트가 같다(워커 1·2개 정확 일치 확인).
- 작업 프로세스가 실행하는 코드는 호출 쪽이 import한 모듈 파일이므로, 매니페스트의 패키지 해시가 실제 실행 코드와 대응한다.
- 비어 있지 않은 화합물 디렉터리가 있으면 작업 프로세스를 띄우기 전에 실험이 멈춘다. 재시도는 새 출력 위치에서만 가능하다.
