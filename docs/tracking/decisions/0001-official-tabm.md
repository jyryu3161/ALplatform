# 0001. 자체 MLP 대신 공식 TabM 구현 사용

## 맥락
버전 1은 `TabMNetwork`라는 자체 MLP와 추론 시 Monte Carlo dropout으로 불확도를 냈다. 이름은 TabM이었지만 논문의 매개변수 공유 앙상블과 달랐고, 불확도의 의미도 불분명했다.

## 결정
버전을 고정한 `tabm==0.0.3`의 `TabM.make`를 수치 지문 입력, 수치 특성 임베딩 없이 사용한다. 학습은 표준화 목표값에 대한 멤버 손실 평균 최소화, 추론은 멤버 평균, spread는 멤버 간 모집단 표준편차. 추론 시 dropout은 끈다. 구조를 복사·재정의하지 않는다.

## 대안
- **자체 MLP + MC dropout 유지**: 기존 체크포인트 호환은 되지만 "TabM"이라는 이름으로 다른 모델을 보고하게 되어 기각.
- **TabM 구조를 저장소에 복사(vendoring)·재정의**: 공식 구현을 그대로 인용·검증한다는 목적에 어긋나 채택하지 않음. 버전 고정은 `tabm==0.0.3` 의존성으로 한다.

## 결과
- 버전 1 체크포인트는 호환되지 않으며 원본 데이터로 다시 학습해야 한다. `mc_dropout_samples`, `embed_dim`, 모델 수준 `max_threads` 설정은 제거되었다.
- spread는 공유 매개변수 멤버의 퍼짐이라 보정된 신뢰구간이 아니다. 불확도 기반 과학적 주장은 별도 평가가 필요하다.
- `tabm` 버전을 올리면 결과가 바뀔 수 있으므로 의존성 변경으로 취급한다.
- 이전 MLP나 MC dropout을 TabM 이름으로 되살리는 것은 불가능한 선택이 되었다.
